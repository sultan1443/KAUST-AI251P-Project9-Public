# M8 — 21 November 2026 Colab follow-up evidence

**Project:** Project 9, Phase 2 · **source:** team-supplied JSON experiment records from `Project9_Phase2/evaluation/M8_DEMO_EVIDENCE/` in private Google Drive.

This page is a faithful **summary of saved team measurements**, **not a fresh GitHub Actions run** or an independently repeated experiment. The seven JSON records are supplied with the **private course source/evidence ZIP**, not published here.

## 1. Local API smoke test

- The private checksum-verified detector and segmenter loaded in a fresh Google Colab session.
- `GET /health` returned HTTP 200: `status=ok`, `backend=PyTorch`, `device=cpu`, `model_verified=true`.
- `POST /predict` on the Validation diagnostic replay `frame_000.jpg` returned HTTP 200.
- The API returned **3 predicted cardboard objects**, **2 associated polygons**, and **1 `requires_review` flag**.
- The output is a successful *functional* inference smoke test. No annotated ground-truth accuracy was measured for that frame.

## 2. HTTP performance and resilience

**Scope:** localhost PyTorch CPU, **2 warm-up calls**, **25 sequential requests** (concurrency 1) using **one repeated Validation JPEG**.

| Measurement | Result |
| --- | ---: |
| Successful HTTP 200 responses | **25 / 25** |
| Client end-to-end p50 latency | **405.09 ms** |
| Client end-to-end p95 latency | **643.95 ms** |
| Client end-to-end p99 latency | **653.87 ms** |
| Requests/images per second | **2.09** |
| Server process RSS snapshot | **864.90 MiB** |
| Invalid image upload | **HTTP 400**, expected failure |

The RSS was a single process snapshot, **not peak memory**. A p99 computed from only 25 requests is unstable. The throughput is for this specific repeated-image and runtime condition; **it does not establish production conveyor speed** or sustained load reliability. These figures are a separate session from earlier recorded CPU HTTP timings and must not be pooled into an artificial performance improvement.

## 3. ONNX exports and backend comparison

The separate exports are `deployment/onnx/detect.onnx` and `deployment/onnx/segment.onnx` in private storage. Both ran with ONNX Runtime **1.32.0 CPUExecutionProvider**.

Comparison settings: same Validation image, nominal input 640, confidence 0.25, NMS IoU 0.50. Box pairing was same-class at IoU ≥0.50; mask-polygon IoU was computed after rasterizing polygons into the original image dimensions.

| Diagnostic | M4 detector | M5 segmenter |
| --- | ---: | ---: |
| PyTorch predicted count | 3 | 7 |
| ONNX predicted count | 3 | 8 |
| Same-class matched boxes | **2** | **6** |
| Mean box IoU **on matched boxes** | **0.998159** | **0.994888** |
| Maximum coordinate difference **on matched boxes** | **0.217 px** | **1.577 px** |
| Mean polygon mask IoU **on six matched M5 pairs** | — | **0.991393** |

**Caveat:** Predictions **did not fully match**, even after trying `rect=False`. M4 has one unmatched item in each backend; M5 has one unmatched PyTorch item and two unmatched ONNX items. The M5 difference included an ONNX prediction at confidence **0.2501** near the 0.25 threshold. High IoU is **conditional on successful matching** and does not establish universal model parity, semantic accuracy or equivalence against ground truth.

A separate older eight-image M5 Validation experiment recorded 38/38 matched predictions and high mask agreement under its own settings; do **not** combine those distinct experiments.

## 4. What this validates — and does not

**Supported:** file-integrity-controlled local startup; valid JPEG HTTP inference; bounded 25-call latency/throughput; invalid-input handling; separate ONNX execution and close matched-object geometry.

**Not supported:** a hosted public API, a service whose backend is ONNX, complete tensor-level parity, full Validation/Test parity, multi-client load testing, guaranteed belt throughput, industrial grasp accuracy, or stable p99 inference from a 25-call sample.
